# Changelog — run-benchmark-driven-rd

## 2026-08-30 — default downstream update obligation

- Routed authorized implementation, promotion and completion of distributable Skill/software/game/installer/release targets through secure update checking by default, while leaving audit and source-only work read-only.
- Added a typed update-obligation receipt, updater risk floors, completion capability floors for the local client and public release channel, and deterministic positive/negative routing coverage.
- Updated the R&D Cleanup adapter to accept only provider schemas 1.1/1.2 and preserve schema 1.2 `update_coverage` plus its D11 status without promoting it.
- Kept GitHub publication, signing, persistence, telemetry and deletion outside the inferred authority of target-project development.

## 2026-08-30 — task-aware routing, learning v2, and secure self-update

- Reduced the canonical entrypoint from 5,242 to 913 exact `o200k_base` Tokens and moved task-specific knowledge into bounded, hash-addressed topic cards with explicit legacy fallback.
- Added task-aware Router v2 contracts, route/context receipts, stable critical rule IDs, and a dedicated GitHub secure-self-update intent without turning URLs into execution authority.
- Added immutable experiment records, a locked atomic JSONL view, typed privacy/scope/promotion fields, topic-index validation, reciprocal promotion receipts, and 32-writer no-loss coverage.
- Added provisional single-owner topics for claims, architecture, context/learning, completion/external changes, and side-by-side updater staging, health, rollback, data migration, opt-in persistence, and safe retirement.
- Added a 39-case deterministic Router v2 quality corpus plus five bounded high-risk cards: all cases, critical-rule recall, required-topic recall, precision, fallback, updater risk floors, and the Token target pass; task-aware p50/p95/max are 2,366/4,114/4,528 estimated Tokens, while six route-external assertions remain honestly `NOT_CHECKED`.
- Preserved both former entrypoints and baseline evidence in private `.rd` migration storage; no public sync, GitHub mutation, or release was performed.

## 2026-08-28 — reproducible project-native gates

- Added contract-declared `projectGates` and string-only `evidenceBindings` for architecture checks that shared modules cannot infer.
- Bound generated project routes to the exact project-contract hash so native gates cannot be added by an unreproducible hand edit.
- Preserved evaluator boundaries: project-native evidence supplements an explicit Cleanup `NOT_CHECKED`; it does not rewrite measurement coverage.

## 2026-08-24 — one-source editorial-unit cardinality

- Added one-long-source → N semantic editorial-unit promotion gates. Independent unit truth, distinct editable projects/renders/receipts, compilation-fallback rejection and material recut fingerprints are now required; old Skill/product outputs remain benchmark-only.

## 2026-08-24 — modular project composition

- Added reusable project modules for Skill, web, database, game, software, release, security, media and commerce work.
- Added a hashed project-route gate and `.rd/project.json` initialization contract.
- Kept Cleanup as an independent read-only measurement provider while R&D owns decisions, experiments, capability closure and release mutations.
- Defined a two-tier learning boundary so project evidence compounds without leaking private or project-specific data into shared/public Skills.

## 2026-08-23 — lazy readiness, evaluator ownership and config scope

- Desktop probes now tolerate a missing initial `document.body` and wait for route-specific lazy landmarks before judging onboarding or decision density.
- Security evaluators follow extracted responsibility modules instead of remaining pinned to a historical entry filename, with negative-fixture replay required after scope changes.
- Repository cleanup uses the target's own audit config and treats generated-dependency inventory explosions as measurement failures.

## 2026-08-23 — isolated desktop controller and readiness semantics

- Desktop journeys now isolate both product state and WebView／browser user-data state without touching the operator's running app.
- Lazy onboarding and workspace transitions wait on bounded interactive predicates; localized copy and fixed sleeps are no longer promotion selectors.
- Beginner-density gates separately cap enabled decisions and disabled workflow signposts, with negative controls for both failure modes.

## 2026-08-23 — durable drag import and semantic edge trim

- Whole-window desktop drop now needs to converge with picker import on durable native paths, media probing, cache, canvas inference and editable Timeline insertion; a browser object URL or decorative overlay is diagnostic only.
- Edge-trim evidence now freezes the opposite edge, frame alignment, one-frame minimum and a single Undo commit.
- Beginner discovery explicitly covers drag-over feedback and unsupported-format messaging.

## 2026-08-23 — beginner findability and packaging authorization gate

- Fresh-profile promotion now separates hidden component presence from the user's ability to find onboarding, automatic editing, material previews and effect／caption preview entries.
- First-run guidance must support complete, skip and permanent reopen paths; automatic editing exposes prerequisites and the next action in-product.
- An explicit development-first／no-package instruction now stops before installer construction and keeps delivery obligations open until the user's acceptance signal.

## 2026-08-23 — semantic Timeline and source-geometry gates

- Timeline promotion now includes hard negative drop regions and forbids source-lane fallback from committing time movement after an invalid vertical drop.
- Ripple-delete evidence measures exact synchronized gap closure and one-step full-graph Undo, not merely clip count reduction.
- First-source portrait／landscape／square inference now runs through the delivered import adapter with decoded metadata, starter replacement, persisted resolution and output-geometry evidence.

## 2026-08-23 — isolated repeat-run delivery gate

- Delivered desktop journeys now use per-run recovery／batch／update／remote state roots and must pass twice without inheriting prior Autosave prompts, queued work or device credentials.
- CDP／WebDriver pending commands are connection-owned; a timed-out socket cannot cascade failure into a newly established controller session.
- Promotion separates controller availability from product responsiveness through independent UI／service probes before assigning the failure class.

## 2026-08-23 — continuous pointer stream and nested-runner closure

- Delivered Timeline promotion now requires real press／multi-move／release continuity, all sampled visible updates, one release-time canonical commit, single-step Undo, Redo and durable Autosave/reopen.
- Separates transient compositor transforms from canonical EditGraph mutation and forbids native-language rewrites as a substitute for fixing missing UI events.
- Nested runners now preserve the primary child failure, await the owned process tree, report cleanup only as secondary evidence, and bound retry loops by wall-clock deadlines with per-stage attribution.
- Raw main, compressed, CSS and lazy-chunk bundle budgets are independent exact gates; small byte overruns cannot be promoted by widening the threshold.

## 2026-08-23 — cold extracted-runtime delivered gate

- Cold extraction is now a distinct delivered state: keep the editor observable while OS security scanning, runtime startup and first library indexing are pending.
- Split unrelated backend work into separately timed stages; one giant awaited CDP／WebDriver promise cannot classify product versus controller failure.
- Promotion retains UI heartbeats and controller misses, then asserts durable project／Autosave／artifact postconditions rather than racing on transient shared status copy.

## 2026-08-22 — non-blocking desktop background-job promotion gate

- Long native IPC work now needs immediate queued acknowledgement plus bounded polling/event completion instead of holding the WebView request open.
- Promotion injects a slow backend and measures concurrent editor input responsiveness, terminal settlement, duplicate coalescing and stale-result isolation.
- Backend success is insufficient if a second UI/CDP probe cannot run while the job is pending.
- Synthetic `beforeunload` dispatch is no longer valid delivered-lifecycle evidence; deterministic guard units and real navigation/native-dialog acceptance are separated to prevent flaky WebView destruction.

## 2026-08-22 — permanent QR device-binding gate

- Promotion now restarts the service/app, reconnects without QR, distinguishes stop from revoke, rejects the old credential after exact-device revocation and scans retained evidence for plaintext secrets.
- Stable origin/port, owned HTTPS, browser storage eviction and lost-device recovery remain separate availability obligations.
