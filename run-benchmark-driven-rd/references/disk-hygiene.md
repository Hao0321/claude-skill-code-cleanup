# 階段性磁碟維護

這是開發工作流的收尾，不是背景排程或 updater 的永久刪檔權限。大型 build／render／解包前，及每個階段結束、失敗重試、交接前，必讀 Cleanup 的 `../code-cleanup-helper/references/disk-hygiene.md`（相對 R&D Skill 根目錄解析），取得工作槽與系統暫存槽的當前空間及精確候選清單。

1. 專案 `.rd/` 記錄空間 baseline、下一輪峰值估計、保護清單與保留上限。至少保留目前 candidate、最後驗證可用版及必要失敗重現；不要把所有歷代 target、解包副本、測試影片都列永久保護。小型收據／錯誤記錄保留，冗餘大產物可淘汰。
2. 使用者已要求清理時，在該範圍內主動清除確認可重建且已停止使用的產物，不必對同一批安全候選重複詢問。純診斷只提案；權限不明、唯一原件、使用中、共用路徑或使用者待審內容先保留並報原因。
3. 刪前重新解析精確絕對路徑，確認落在批准的生成物子目錄；檢查全部祖先與候選子樹，不跟隨連結；拒絕根目錄、父層逃逸、symlink／junction／reparse point 及跨界項目。重查活躍工作、來源／收據與候選身分；有 drift 即停。Windows 使用同一 PowerShell 流程和 `-LiteralPath`，不把路徑拼到另一個 shell 執行。
4. 優先可恢復操作；若目的是實際釋放磁碟，回收筒／同槽 quarantine 不算回收。僅對已授權、可重建且非唯一證據的精確清單永久刪除，事前說明；遇到鎖定或拒絕存取就略過，不強殺／關閉使用者程式，不改權限繞過。
5. 每段清完量測 free bytes，記錄實際刪除／略過及可恢復性，驗證目前版、rollback 與原始素材不受影響。新清理帳本引用舊 receipt SHA，將已刪實物標記 retired；不改 immutable receipt、不把失敗蓋成 PASS。沒有安全候選或空間仍不足就明確回報，不再盲目開大型重跑。

若只有操作規則更新，驗證可只做合約／情境檢查；不得宣稱已部署自動清理程式。清理實作與成果必須另有當次檔案、磁碟和 protected-state 證據。

多代產品清理的 claim matrix 至少分開量測：候選閉集預檢、當前指標及其世代、活躍程序可能持有的舊世代、最後可用回退版、原始素材與可編輯專案、發佈／待審成片、可重建測試產物。負控制要包含「暫存目錄存在但不合候選契約」及「指標切換後仍有舊程序」；兩者不能因檔名或日期而被誤判可刪。釋放空間的結果以刪後 free bytes 為準，不以候選 logical bytes 或同槽搬移推算。若自動審核拒絕精確刪除，保存拒絕與未完成狀態，不改用別的工具繞過。

被拒時改交付人執行的清理腳本（精確 allowlist、預設 dry-run、`--execute` 才刪、寫日誌），只列本輪可由對話紀錄或建置腳本證明的暫存；保留可重用成品與原始量測，只刪中間建置。Windows Git Bash 的 grep 可能 core dump 並留下 `grep.exe.stackdump`，改用內建 ripgrep 並清掉殘檔。新暫存先選有餘裕的磁碟。
