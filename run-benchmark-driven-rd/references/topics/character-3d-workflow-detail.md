# Modular 3D character workflow (provisional)

R&D implements; Cleanup audits.
At setup/requirement changes, reconcile the
[production profile](../character-production-profile.md) with the user's contract.
For resumed repair or new edge flow, read [retopology](character-retopology.md).

Check global UV, fresh skin roles, continuous transitions and reloads. Crooked
face: distinguish pose from rest shape first. Optional separately installed
helper: resolve `game-mesh-repair/SKILL.md` from the host's active skills;
it is not included in this two-skill package.

- `rd.character.inputs`: lock approved design, scale, pose and handedness; split complete bald head, hair with scalp clearance, and headless body. Front/side/back consistency precedes paid 3D variants. Screenshots are design evidence, not models. Confirm missing back views, source rights and generation budget.
- `rd.character.assembly`: preserve originals; inspect fit and use [mesh repair](character-mesh-repair.md) for defects before UV/rigging. Bounds alignment or Join is not topology repair. Freeze topology before skin/morphs; remesh requires renewed correspondence and deformation tests.
- `rd.character.rig`: exact Unreal compatibility needs the actual target reference hierarchy/rest transforms, engine readback and animation. Similar bone names are only a custom retarget candidate. Normalize deform weights without destroying masks; test transfer distance and joints. Hair/cloth chains belong to a deliberate skeleton hierarchy; bones alone are not physics.
- `rd.character.rig-guide-branch`: when head/body are assembled and calibrated, an external service's humanoid rig can be evaluated as a *guide* only with explicit upload/credit authority, real exported file, rest-pose and bone mapping. Confirm its actual format; a provider advertising rigged FBX/GLB does not establish direct VRM 1.0 export or Unreal Mannequin compatibility. If a compatible manually painted base exists, project its weights by pose/scale-aligned surface correspondence and semantic masks, not vertex index. Validate normalisation/influence caps, eyes/lids, neck, hands, knees, sleeves/skirt and pose return. If the base is absent, report the dependency; do not hallucinate a weight transfer. Binding an unweighted head and entire wig rigidly to a head bone can check alignment and turn behavior while preserving source weights, but it leaves independent strand/cloth motion open. Freeze/recheck geometry before the transfer and test in the exact engine separately.
- `rd.character.expression`: same topology/order supports blendable morphs; independent generated topology needs registered discrete heads. Export and test the runtime selector. Shrinking hidden heads inside a skull is not a portable general solution. Leader/master-pose extra bones and independent dynamics need separate engine validation.
- `rd.character.texture`: audit UV overlap/degeneracy/stretch/density before repaint. Prefer semantic seams for faces; Smart UV is a draft. Preserve original UV/materials. Export fixed-camera flat-color views, geometry/UV hashes and visibility; Imagegen edits keep pixel registration and identity. Agent generation is distinct from a Blender API. Reproject with occlusion/angle rejection and coverage; prompts/coverage cannot prove visual quality. For NPR, use [NPR normals](character-npr-normals.md); do not impose a PBR-map goal.
- `rd.character.ue-material-readback`: source-tone material instances can make an imported asset viewable but do not satisfy NPR. In UE 4.27 Python, do not trust a successful save after mutating returned `SkeletalMaterial` slot structs alone: one local three-slot skeletal mesh lost all assigned interfaces on cold reopen. Rebuild explicit structs with the intended `material_interface` and slot names on an isolated derivative, save, restart the editor, and verify each mesh slot plus each instance's parent/texture and any preview actor override. Treat this as a version-specific measured fallback, not a universal API rule.
- `rd.character.uv-storage`: audit stored UV precision and save/reload, not only the solver's floating-point plan. Packing can collapse thin triangles after float32 storage. Keep a planned-pass/stored-fail control. Zero overlap and fewer islands do not establish paintable face charts; inspect the actual checker and seams before repaint.
- `rd.character.uv-fragmentation`: measure vertex-connected mesh components and UV charts separately before planning seams; disconnected lashes, hair strands and dress ornaments may be legitimate, while hundreds of UV charts on far fewer physical parts make a source atlas hard to repaint. Render the real source UV triangles with chart coloring and verify overlap/degeneracy per mesh. Do not treat a low geometric component count as proof of paintable UVs, or remove small disconnected ornament pieces on that basis.
- `rd.character.hair-uv-pilot`: on a source-preserving derivative, split genuine multi-face fans only with corner/normal preservation checks, then draft semantic hair charts and run stored-UV quality on the saved/reloaded copy. Measure degenerate UV triangles **per geometric component**: fewer charts can conceal a collapsed cap-plus-strand component. If a coarse crown/front/back cut increases collapse, reject it and change the component's structural flow or cut path; never relax degenerate thresholds or rebake the failed atlas.
- `rd.character.hair-orientability`: distinguish vertex-touch connectivity from edge-connected surfaces. A fan-free generated hair shell can have many boundary loops and non-orientable face adjacency; local winding seams and ANGLE_BASED/CONFORMAL swaps can all retain hundreds of collapsed UV triangles. Use the tested read-only topology preflight, then reconstruct or structurally cut the offending shell and rerun geometry/corner/UV/native gates. The the source project source-specific counts remain project-local, not universal thresholds.
- `rd.character.user-density-override`: if the user says the current generated character is already low enough, stop global decimation/LOD pilots for that asset. Limit geometry edits to individually measured defects, preserving coordinates, materials, skin weights, neutral and posed evaluated meshes; record any removed zero-area redundancy separately from density reduction.
- `rd.character.component-hybrid-uv`: compare original and proposed UVs on identical, cold-reloaded edge-connected surfaces. Keep validated semantic panels; selectively reuse source UV for intact small surfaces; localize overlap/stretch witnesses on failed surfaces and patch only the smallest measured set. Then run whole-atlas exact overlap/degenerate/aniso, island count, occupied UV area, texel density, saved float32 and native art checks. A global Smart Project can replace a few local defects with hundreds of tiny charts and is not a paintability win. A source-colour UV rebake is a correspondence check, not new NPR art.
- `rd.character.triangle-chart-hair`: when seam heuristics still fold a fused hair shell, trial an isolated open-source triangle-chart atlas (for example xatlas) against the frozen source. Reassociate output triangles by source vertex IDs, not assumed face order; detect quad corners receiving incompatible UVs, split only those quads on their existing triangulation diagonal, and verify unchanged positions, triangle identities, material assignments, skin weights and old UV correspondence. The native atlas may still contain a few overlaps despite library packing; localize exact witnesses, isolate only measured faces and repack. Accept only after cold-reloaded zero overlap/degeneracy, distortion/density/padding, native source-colour rebake and paintability review. Record package version/license and keep any installed wheel out of a distributable skill unless its redistribution is deliberately reviewed.
- `rd.character.hair-orientation-cut`: a read-only dual-graph parity plan can identify a small set of contradiction edges; an isolated edge split may preserve triangles, UV corners and weights while making the surface topologically orientable. Measure added vertices and rerun UV/pose/normal gates. Crucially, orientability is not consistent **existing** winding: compute how many faces would have to flip and require native culling/shading and art checks before doing so. If that count is large, keep the split pilot unpromoted rather than claim broken-face repair is complete.
- `rd.character.hair-two-sided-gate`: a second measured split of current same-direction shared edges can remove local winding conflicts without changing face corners or flipping normals. Check cold topology/UV, exact two-sided A/B images, then explicitly simulate one-sided backface culling from front/quarter/back. Pixel-identical two-sided renders can coexist with missing one-sided strands; preserve this as a separate material/engine-performance decision, not a geometry PASS or permission to merge into the motion rig. A back-scalp coverage hole is independent of winding conflicts.
- `rd.character.render-uv-channel`: distinguish Blender's active editing/bake UV from `active_render`. Explicitly feed the original UV to the source-colour shader, bake to the new active atlas, then switch the atlas to render UV and cold-render front/quarter/back. Diagnose large black patches against this channel state before blaming the UV layout.
- `rd.character.ai-atlas-gate`: a generated atlas candidate must match the requested exact pixel dimensions, UV-island mask, motif placement and native mesh appearance. Store prompt, input/output hashes and failed candidates. Even a visually cleaner small preview must not auto-promote if downsampled or shifted; a reference image does not become a production base-color map. Follow image generation with the same exact UV, mip/edge and native-engine gates as manually authored maps.
- `rd.character.ai-detail-layer`: if a whole-atlas image edit fails exact registration, test a generated material swatch only as a separately controlled detail layer over the validated base atlas. Check claimed tiling numerically at all borders, mask by semantic fabric/skin ownership or calibrated color—not luminance alone—and render full plus close views before/after. A composited 2K rebake must preserve existing motifs, exposed skin and UV edges and remain review-only until artist and engine acceptance. Do not call a fabric-only sharpen pass a complete character repaint.
- `rd.character.registered-part-space`: source head/hair/body parts can each use normalized unit-height local vertices while intended assembly lives in distinct scale/translation matrices. Matching matrix values between two later **unregistered** derivatives are not evidence of alignment. Bind the original registered matrices/hashes, compare world-space part bounds and front/side/back after a cold reload, and isolate any coordinate correction from mesh, UV and rig edits. Only then judge true silhouette/coverage issues; a correctly scaled wig may still expose the back scalp.
- `rd.character.ornament-reconstruction`: a generic AI microtexture with a calibrated color mask can preserve UV registration but fail to improve a blurred emblem's actual silhouette. Keep full and matched close-up A/B plus a visible-change/motif-recognition gate. If the contour remains soft, reject the layer and reconstruct the individual decal in registered UV space; do not claim the material has been regenerated from subtle grain alone.
- `rd.character.registered-current`: build every lab, demo and fixture character from the owner-registered character CURRENT (path plus sha256 pin), never from downloads, original source archives, an older repair folder or the newest-looking file name. The builder verifies the pin and writes a manifest with the source hash; every consumer refuses a build whose manifest does not match the live pin. When a repair line leaves dozens of intermediate folders pinned inside the owner's `current`, those history paths get picked as work inputs: keep CURRENT plus one PREVIOUS, move history to the journal and let the human run the retirement (Recycle Bin, not permanent deletion). After the user says "start from the latest", start from it even if it is unaccepted, record what it still lacks and do not revert to an earlier base.
- `rd.character.head-uv-standard`: the head skin unwraps into exactly four charts: the whole front face, the back of the head, the left ear and the right ear; separate eye, teeth, tongue and lash pieces remain their own charts. Detect ears as thin lateral flaps by shape diameter: cast a ray inward from each face, skip hits on the face itself or faces sharing its vertices (non-planar quads otherwise report 0 mm), and treat a diameter below about 0.2 head half-widths beyond about 0.55 half-widths from the centre plane as a flap; take the largest connected flap per side and add rim/cap faces by two neighbour-majority closing passes. Lateral extent alone selects the wide cranium and smoothing displacement is noisy on irregular triangulation. Artist labels always win. Verify with a chart-coloured front/side/back render, the UV image and a synthetic eared-head regression (thin flaps, correct side, four skin charts).
- `rd.character.uv-transfer-sharpness`: re-UVing a painted AI atlas is a resampling step. Bake source colour through the old UV into the new UV and compare same-camera close-ups of eyes, lashes, hair edges and ornaments, not only full-body views. A uniform semantic density loses the extra texels the source atlas gave the eyes: raise the face/outfit texture to 4K or emphasise front-face charts, and repack tightly (a budget shelf packer can leave ~45% coverage). Bake at the target size with jittered samples instead of 2x then image-scale (which softened detail). If every semantic unwrap of generated hair cards collapses a large share of the surface, fall back to angle-split charts plus equal-density packing and record it; never relax the collapse threshold. Keep a part on its old UV only with a written reason.
- `rd.character.blender-batch-pitfalls`: in background Blender, pass absolute output folders (bare relative image paths resolve against the drive root); give new images absolute paths, save the .blend, then make paths relative; disable `.blend1` versions for deliverables; shape-key blocks take no ID properties (keep saved values in a dict); pass argparse values that start with '-' as `--right=-1,0,0`; gate subprocess success on exit code and Python tracebacks, not on the word "Error" (GPU-driver warnings contain it). `bmesh.ops.split_edges` on fan edges keeps shape keys, weights and custom normals on rigged meshes, whereas the repair add-on refuses rigged meshes.
- `rd.character.hair-strand-albedo`: give generated or rebuilt hair painted strand detail from its flow UV (V along the strand): fine lines every few millimetres for close-ups, a sparser family of crisp, tapered parting strokes at least ~2 mm wide (broken into strokes a few centimetres long so they never read as wood grain) for bust distance, a few light strands, and only weak broad clump shading; broad soft valley darkening reads as obvious stripes. Measure the baked texture's contrast numerically (hair-texel percentiles) because studio-lit previews exaggerate faint lines, then verify in the engine at bust and close distances; if a high-contrast swap texture shows detail but the hair does not, the hair albedo is too flat, not the UV or the shader.
- `rd.character.gates`: calibrate positive and defect fixtures for topology, weights, UV, stale projection, missing views and engine receipts. Scope PASS by stage; real imported character appearance, deformation, expressions and physics need native visual/runtime evidence. Keep raw models, screenshots, paths and test logs project-local; publish sanitized workflow only with current authority.
