# Agent workflow adoption

For external skill/plugin adoption; pair with the independent [Cleanup audit](../../../code-cleanup-helper/references/topics/agent-workflow-audit.md).

- `rd.workflow.selective-adoption`: freeze upstream/port revisions, license and effective policy differences. Compare existing capabilities; adapt the smallest useful mechanism. Tools, hooks, agents, model defaults and external writes require separate scoped decisions, not inherited authority.
- `rd.workflow.project-driver`: build/reuse a project-local recipe from observed code: launch an isolated usable instance; check identity/readiness read-only; drive stable user-facing commands/selectors; capture actions/durable results; tear down owned state, retaining proof. Map features to entries; run one representative journey before handoff. Unrun features stay unmeasured.
- `rd.workflow.structural-correction`: for a recurring real mistake, consider removing ambiguous ownership/unsupported paths before type/schema constraints, lint or behavior tests. Replay the defect and a valid control. Document remaining judgment; preserve unique evidence, supported compatibility and out-of-scope changes.
- `rd.workflow.load-bearing-fact`: identify the change's crucial assumption, trace consumers beyond direct imports and run the actual pinned function/app path that can refute it. Bound the proof; explanation or reviewer agreement is not execution evidence.

Design input: Lauren Tan's MIT [pstack](https://github.com/cursor/plugins/tree/4382e687a50b8d2c5ce4d141d001186589cff8d5/pstack): verification, correct, blast-radius. Original provisional rules; no upstream runtime. Fixture success does not establish overall agent-quality gains.
