# Transaction and identity integrity experiments

Apply to persisted business records, financial actions, account migration, recovery and cloud replacement. Load Cleanup's `../../code-cleanup-helper/references/topics/state-integrity-audit.md`. Repairs follow existing authorization; this topic does not imply publishing or touching production data.

- real chain: freeze a claim matrix spanning UI, persistence, acknowledgement and restart. Use an isolated store and the production adapter, preload and IPC handlers. Pure validation tests measure their own scope and cannot substitute for the delivered caller journey.
- adversarial replay: measure rejection before commit separately from reply loss after commit. Pair each legitimate journey with quota failure, malformed data, stale stock/identity, repeated original ID, changed contents, unauthorized frame/caller and mid-transaction failure. Compare money, points, stock, cart and complete backup inventory; include historical rows beyond UI limits and cumulative partial refunds.
- learning transfer: run Cleanup's generalized `scripts/state_integrity_regression.py`, then replay the target's real regressions. Store the typed experiment and reciprocal sanitized promotion receipt; one project plus generalized replay can support shared guidance. Keep names, paths, credentials, raw logs and metrics local. Report actual source/runtime scope and external gaps; zero dependency advisories or local SQL success is not product parity or deployed security.

Prefer a narrow repair with falsifiable receipt and restart behavior over accumulating source-only checks. Keep unresolved cloud conflict merging, signed releases and real-device acceptance explicit. Do not request approval for repairs already authorized.

When the user chooses a shared store, freeze the single-authority and disconnected-client contract separately from independent offline use. Extend the real journey to concurrent transport clients, native changes observed remotely, one original journal after reconnection, revocation/expiry and a replacement database at the same URL. Pair legitimate re-pairing with fragment-only navigation in an already open tab. Test full stock/purchase/catalogue atomicity, stale counts, known historical receipts, cash deposits bound to a shift, explicit zero settings and restored business identity. Treat absence of a retry button during saving as pending, not completion.

Shared promotion must keep immutable experiment links, both fixture groups and prior receipts through index rebuilds. Record project counts and raw receipts locally; generalized calibration remains a separate measurement. Phone-size Chromium plus an exact fixture certificate proves that caller path, not installation/trust on iOS or Android, physical printing, deployed cloud policy or installer delivery.

Extend caller fixtures to native commands and public attributes: fixed program plus literal arguments/environment, context-correct escaping, failed child acknowledgement and legitimate UI actions. Separate loopback transport and mocked spooler evidence from physical printer acceptance.

Transfer evidence: [sanitized promotion receipt](../profiles/state-integrity-promotion.json).

For reservation and fulfilment repairs, compare uncooked release with consumed cancellation under one authoritative stock, capacity and ledger transaction. Keep frozen unit costs, actual loss expenses, mixed cash/noncash tender accounts and the store calendar consistent across UI, reports and restore. Preserve linked financial history instead of deleting proof. Calibration needs a historical timestamp and tied-order restore control, not only a fast same-second round trip. A source journey that passes before repackaging still needs exact payload, fresh startup, restart and a verified previous-version fixture before a local delivery claim.

Fractional inventory and calendar experiments must use actual caller inputs, not just adapter values. Pair fractional and integer units with rejected precision/sign/stock, delayed acknowledgement, quick-action double clicks and original-ID recovery that completes the original form. At local day/month rollover, compare report selection and date inputs with saved ledger dates and parsed timestamp intervals. Verify an injected clock in the final page context before interpreting results; a navigation or unfinished resize may invalidate the probe rather than reveal a product defect.
